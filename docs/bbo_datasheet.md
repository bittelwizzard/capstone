# BBO Capstone Data Sheet

## Motivation

This data set was created for the Black-Box Optimisation capstone project.

It supports the task of finding high-value inputs for eight functions when the function formulas are unknown. Each query has input values between zero and one and produces one numerical output.

The data set was created and maintained by the project author. No external funding is recorded.

## Composition

The data set contains initial observations and later query results for eight functions.

The initial data are stored in `function_1` through `function_8`:

- `initial_inputs.npy` contains the input arrays.
- `initial_outputs.npy` contains the matching output arrays.

The later data are stored in weekly folders:

- `inputs.txt` contains the submitted query points.
- `outputs.txt` contains the returned function values.

The data are a sample of the possible input space. The function formulas, true optimum values, noise measurements and untested candidate points are not available. The data contain no personal or sensitive information.

## Collection Process

The initial observations were provided for each function. Later observations were collected during the weekly project rounds.

One query was submitted for each function in each round. Later queries were chosen using the results from earlier queries.

The main later-round strategy used a Gaussian process and an upper confidence bound. This strategy used previous results to find a balance between promising areas and areas that had not been explored much.

The round-10 queries were generated by [scripts/propose_week10_queries.py](../scripts/propose_week10_queries.py). The script used fixed random seeds and kept all input values between zero and one. It used more possible candidate points for functions with more input variables.

The data are organised by project week. Exact collection dates were not recorded.

## Preprocessing and Cleaning

The initial NumPy files were used in their original numerical format.

The weekly text files were read and combined with the initial data before fitting the optimisation model. Query values were limited to the range zero to one and written to six decimal places for submission.

No missing values were filled in. No labels were added. No unusual results were removed. The original input and output files were kept.

The data were not divided into training, validation and test sets because this was a sequential optimisation task. Earlier results were used to choose later queries.

## Uses

The data set can be used to:

- Reproduce the BBO query process.
- Review the results from each project round.
- Study optimisation with a small query budget.
- Compare exploration and exploitation decisions.
- Study the effect of input dimensions on search coverage.

The data set should not be used to claim that the global optimum of any function was found. It should not be treated as a complete or evenly sampled description of the functions. It should not be used as evidence that the functions are smooth or that the results are repeatable.

The data set is not suitable for safety-critical or production decisions. There are no repeated measurements and no guarantees about measurement accuracy.

## Distribution

The data set is stored in this project repository. It includes:

- Initial NumPy data.
- Weekly input and output files.
- Query-generation scripts.
- Project reflections.

No external API or hosted data service is used.


## Maintenance

The project author maintains the data set and documentation.

For each new round, the input and output files should be stored together in a clearly named weekly folder. Existing raw files should not be overwritten.

Future updates should record:

- The date of the round.
- The software and package versions.
- The query-generation settings.
- The number of candidate points considered.
- Any changes to the optimisation strategy.
